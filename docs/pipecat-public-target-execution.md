# Public Pipecat target execution

## Purpose

ConversationAgentEvals (CAE) can evaluate the public demo at `https://www.pipecat.ai/` as a real external voice target. The executor does not automate a browser. It asks the public demo to start the selected bot, joins the returned ephemeral Daily room with Pipecat's server-side Daily transport, sends newly synthesized caller speech, and captures the target's current-run responses.

This is distinct from the optional Playwright smoke in `scripts/pipecat_public_voice_smoke.mjs`. The smoke checks the public browser experience. The target executor supplies evidence to CAE's normal run, scoring, timeline, and vCon flow.

## User flow

1. Open **Targets**.
2. Select the seeded **Pipecat public demo** target, or create a voice target of type **Pipecat demo**. Its endpoint is fixed to `https://www.pipecat.ai/`.
3. Choose **Try it Out**.
4. Select a benchmark scenario, set the bounded exchange count, and start **Run Evaluation**.
5. CAE submits the scenario's opening user turn as synthesized speech, observes the public target's response, and continues with adaptive tester turns until the configured bound or runtime termination condition is reached.
6. CAE displays the run using the same result surfaces as other executions.

The executor supports `max_exchanges=1..10`; the execution request defaults to three exchanges when no override is supplied. The first caller turn comes from the scenario opener. Later caller turns are generated by CAE's reference tester from the scenario contract, conversation history, and observed target response. This is bounded sequential evaluation, not simultaneous-talk or barge-in testing.

## Execution contract

The target has these launch defaults:

| Field | Value |
| --- | --- |
| target | `pipecat_public_demo` |
| mode | `pipecat_webrtc` |
| tester | `pipecat_tester` |
| executor | `pipecat_public_daily` |
| audio transport | `pipecat_daily_webrtc` |
| public bot | `10-gradium` |

The API rejects incompatible executor and transport combinations. The target endpoint is allowlisted and cannot contain credentials, query parameters, or fragments.

## Runtime sequence

```text
CAE API
  -> local Pipecat service: scenario + opening caller text + exchange bound
      -> Kokoro: synthesize current caller speech
      -> pipecat.ai /api/start: request an ephemeral Daily room and token
      -> DailyTransport: join as "CAE Pipecat tester"
      -> RTVI client-ready
      -> public bot greeting completes
      -> for each bounded exchange:
           publish caller PCM in real-time chunks
           <- target audio + RTVI transcription events
           measure tester-speech-end to first audible target speech
           generate the next tester turn from observed history when another exchange is requested
  <- caller/target WAV evidence, transcript turns, connection state, exchanges, and latency
  -> standard CAE evaluation, timeline, artifact, and vCon pipeline
```

The public room URL and token remain inside the Pipecat service call. They are not returned to the CAE API, written to artifacts, placed in vCon metadata, or included in the saved run snapshot.

## Evidence and provenance

A successful conversation contains:

- caller and agent transcript turns observed during the current Daily session;
- the public bot's final recognition of each accepted caller turn;
- current-run synthesized caller audio and target response audio retained for the run;
- per-exchange latency from tester speech completion to the first audible target speech frame when observable;
- response-completion and overlap metadata when the public transport exposes those boundaries;
- connection milestones such as room connected, target joined, bot ready, and response complete;
- normal CAE evaluation findings, timeline, recording metadata, and vCon export.

The run is labeled as a live external connection using direct Daily WebRTC and current-run synthetic caller media. It is not labeled as browser evidence, a phone call, SIP, saved replay, or fixture-backed scoring.

## Configuration and readiness

The API and Pipecat service must share `REFERENCE_AGENT_INTERNAL_TOKEN`. The API uses `PIPECAT_SERVICE_URL` to reach the Pipecat service. The Pipecat service requires a reachable `KOKORO_BASE_URL` and its configured Kokoro model and tester voice.

Multi-exchange runs also require a working configured tester model because CAE generates follow-up caller turns after observing the target. The target itself remains the fixed public Pipecat bot; selecting a CAE target model does not change the public bot.

The Pipecat image installs the `daily` transport extra. No Node.js, Playwright, Chromium, microphone device, or browser permission is required for this executor.

Because the destination is a public external demo, runs also require outbound access to `www.pipecat.ai` and Daily. Availability, agent identifiers, protocol details, capacity, and behavior remain controlled by those services.

## Failure behavior

The conversation fails without fabricated evidence when any required stage cannot complete, including:

- caller speech synthesis failure;
- failure to obtain a valid ephemeral room and token;
- room connection or remote-participant timeout;
- missing bot readiness;
- no final caller transcription for a delivered caller turn;
- no final target transcript for a required response;
- no captured target response audio; or
- response or whole-session timeout.

Public-service exceptions returned to the API are intentionally generic so room credentials cannot leak through error strings. The direct executor never falls back to a saved transcript or browser smoke artifact.

## Verification strategy

Automated tests cover target validation and defaults, executor/transport compatibility, Pipecat-service response parsing, multi-exchange evidence, artifact persistence, transcript conversion, latency metadata, and run provenance. A live opt-in check should also confirm that the current public service accepts a direct Daily participant and returns grounded transcript plus response audio for the requested bounded flow.

The browser smoke remains useful as a separate compatibility check because it exercises the public site's own UI and browser transport. Its success is not used as evidence for a CAE target evaluation.

## Acceptance criteria

- The target appears under **Targets** as a public voice target.
- **Try it Out** opens the normal run configuration with the direct Daily defaults.
- **Run Evaluation** is enabled without checking for Node.js or Chromium.
- The configured `max_exchanges` is passed to the public duplex executor within the supported 1–10 bound.
- A successful run contains current-run caller and target transcript turns plus captured target response audio.
- Multi-exchange runs retain ordered turns and per-exchange response-latency evidence.
- The result exposes direct-WebRTC provenance and never claims browser, SIP, or phone execution.
- Ephemeral Daily credentials do not appear in API responses or saved artifacts.
- A missing external dependency produces a failed conversation, not replayed or synthetic target evidence.
